# Kiosk mode

- `?kiosk=<seconds>` runs vehicles mode unattended for a wall screen: pick a vehicle the URL's filter allows, chase it, switch after the dwell (default 180 s) at the next stop arrival, capped 120 s later. `&kioskIdle=<seconds>` sets how long a pause lasts (default 120 s, `IDLE_MS`); both are read like each other — a positive whole number of seconds, else the default (`parseKioskSettings`). Neither is part of `Filter`, so neither reaches the subscription variables.
- A run is a **session** (`KioskSession`: `id`, `dwellMs`, `idleMs`) held by `useKioskSession` in `MapView`. A `?kiosk` link loaded cold is read on the first render, as before; afterwards the session is mirrored into the URL with `history.replaceState` (`withKioskParams`, pure): `kiosk` while a session exists, `kioskIdle` only when it is not the default, neither once stopped, no other key touched. `useKiosk` takes the session: a new `id` resets the machine, re-reads the setup from the URL (the filter is synced there continuously, so this is what the filter panel shows) and restores it once — so `?mode=situations&kiosk` is in vehicles mode at once rather than at the first pick, which with nothing matching may be hours away. A stopped run's callbacks — a flight still landing — are dropped (`liveRun`).
- The **Kiosk** tool (vehicles mode only, `KioskPanel`) sets the dwell and idle time from fixed choices, shows what will be chased from the filter (edited only in the filter panel, so the two cannot contradict each other), and has Start, Stop and Copy link — the current URL with the panel's kiosk params, which works while stopped too. Start begins a fresh run that is not paused: its pointerdown fired before the run existed. The tool is hidden with the rest of the controls while the run is running, so its running view is what a paused run shows. **Stop is only in the tool**, never on the paused pill: the pill is what a passer-by touches, and a wall screen must not be ended by accident. Start and Stop each call `leave` once, in `useKiosk`'s `start`/`stop` callbacks rather than an effect: at a stop the last chase stops and the selection clears; at a start the person's own chase ends, which would otherwise run on under "Waiting for vehicles…" until the first pick.
- Every decision is pure in `src/domain/`: `kioskCandidates.ts` (what to pick), `kioskJourney.ts` (stood still, journey ended, arrived at a stop) and `kioskSchedule.ts` (the phases, `step`, and `effectsOf` — the side effects of each transition). `useKiosk` only ticks the machine, listens for input and performs effects; it performs them in the callback where the transition happens, never in a React effect, so each runs once. The restore at a run's start is not a transition and is the one effect; a stop is done in the `stop` callback.
- Candidates come from `useKioskCandidates`, a lean `vehicles` query polled every 60 s with the previous result kept — **not** the live subscription, whose box during a chase is the few kilometres around the chased vehicle. "Good" (monitored, seen within 10 s of the fetch, moved ≥ 100 m since the previous snapshot) is preferred; anything within maxDataAge is the fallback. Before either, a vehicle publishing a line code is preferred (`hasLineCode`): about a third of the feed publishes none — whole codespaces, with no destination either — and the caption then says "No line published" rather than leaving the line pill empty. A filter for such a codespace still chases its vehicles. Both ages are measured at the snapshot's `fetchedAt`, never at the pick: against the pick's clock a 60 s poll and the 30 s default maxDataAge left about half of all picks with nothing eligible. A failed poll keeps the previous snapshot and retries, but logs a `console.warn` (unless the request was aborted by teardown), so a broken query does not hide behind an endless "Waiting for vehicles…".
- The kiosk drives the app through the same callbacks a person does — `MapView`'s `startChase`, `stopChase`, `switchMode`, `setCurrentFilter` — so 3D, padding, route, timetable and the chase camera need no kiosk awareness. `leaving` waits 1.5 s for the chase's exit ease, `arriving` is one `flyTo`, and `lockingOn` waits for the target in `data` (15 s, then pick again). The flight owns the subscription's bounding box, as a chase does: when it starts, `watchArea` sets the box to the view it will land on (`viewBoundsAt`, `src/domain/vehiclesInView.ts`) and `CaptureBoundingBox` is paused while `arriving`. Left to `moveend`, the box stayed on the area being left for the whole flight, and the target first appeared on landing — under a second before the chase began.
- `effectsOf` emits `leave` on entering `leaving`, on any move from a phase with a target to one without, a pause aside, so a chase that ends early is stopped even when nothing matches the filter, and on every move out of `paused`, after `restoreSetup` — once, however many of those rules match — so a resume that lands in `waiting` does not leave the visitor's chase running under "No vehicles match". The first `leave` starts the chase's exit ease (`stopChase` unmounts `ChaseCamera`) and the ease to 2D; a second is a no-op, because no chase remains and the dimension is already 2D.
- A tick that moves into `picking` resolves the pick in the same `step`, so a switch is one transition — chasing straight to `leaving` (or `waiting`) — with one `leave` and no "Finding a vehicle…" frame. Only the Resume button, whose event carries no pool, shows `picking` for a tick; nothing is chased then. Every `flyTo` is level (`pitch: 0`, `bearing: 0`) whatever ease was cut short.
- A chase ends early on the target being gone from `data` for `ABSENT_GRACE_MS` (60 s), not on its first absence: the live cache drops a vehicle after maxDataAge, and AKT, SKY, FIN, OST and TRO report about once a minute. `kioskWorld` carries the absence beside the stillness in one `KioskTrack`, reset on `leave`. Locking on still needs the target present now.
- Any `pointerdown`, `wheel` or `keydown` pauses it (input within 1 s of the last is not recorded again, sparing a render per wheel tick); 120 s without input, or the pill's Resume button, resumes it and restores the setup the screen loaded with (`restoredFilter`, mode, layer switches, and the phone's detail sheet back to `peek`). A pause during `arriving` emits `holdCamera`, which stops the flight (`map.stop()`) so the camera stays where it is; in any other phase the camera is left alone and a chase keeps running for the visitor. The app's controls, the detail card and the chase HUD (`hudHidden`) are hidden only while it runs; the attribution never is.
- `KioskOverlay`'s band reports its height into `mapBottomInset`, so `MapBottomPadding` stays the only writer of the bottom padding. Its height is fixed (`BAND_HEIGHT`) and the "Next" line is always reserved: a padding change jumps the camera, and a band that resized with its content cancelled the leaving eases and stranded the pitch. On a phone there is no band: the sheet stays and only the pill shows. The band's stop strip shows cancelled calls as delivered — "—" and a struck-through name in `SEVERITY_SEVERE`, as `StopRow` does — and marks the first non-cancelled call with `palette.selection`; the progress line is neutral (`text.secondary`), since selection marks only what is selected.
- **Fixed view** is the kiosk's second kind: `?kioskView=<lat>,<lon>,<zoom>,<pitch>,<bearing>` (with `view=3d` for 3D, the URL's filter and `kioskIdle`) holds one camera and shows every vehicle in it through the ordinary subscription, whose box is that view — for a bus terminal on a wall screen. No band, no HUD, nothing chased; the controls are hidden as in a chase. `KioskSession` is a union on `kind` (`chase` | `fixed`); `parseKioskSettings` prefers `kioskView` when a link has both, and `withKioskParams` writes one key or the other, with literal commas, never `view`, which `useViewDimensionQueryParam` owns. It is run by its own hook, `useFixedViewKiosk`, not `kioskSchedule`'s machine: running or paused (`kioskFixedView.ts`) is all it has. Input pauses it and hands the visitor the app; after the idle time or Resume it `leave`s, restores the setup **and the dimension**, and flies back. Camera parsing and rounding are in `fixedCamera.ts`; pitch is capped at 60° (`MAX_FIXED_PITCH`), below the free 3D view's 80°. Two ordering rules: a cold link opens `<Map>` on the camera (`initialViewState`), and while it runs `ViewDimensionLayers` eases to the fixed pitch/bearing rather than `cameraFor`'s 55°, read from a ref so a pause or resume moves nothing by itself; the camera is placed from an effect so its flight starts after, and is not cancelled by, a dimension ease in the same commit. The Kiosk tool's "Kind" select chooses; Start and Copy link take the map's camera at the click. Input listening is shared with the chase kiosk in `useKioskInput`.
- `window.__kiosk` (phase — `fixed` or `paused` for a fixed view — cleared when no run exists) and `window.__kioskIdleMs` (idle override, which wins over the session's idle time; `tests/kiosk.spec.ts` sets 6000 ms) exist in development builds only.
